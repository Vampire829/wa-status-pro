# WA Status Pro

Самостоятельно размещаемая панель для блогеров, у которых аудитория живёт в статусах WhatsApp, а телефон уже не тянет тысячи контактов. Программа стоит на вашем VPS, подключается к вашему номеру как связанное устройство (как WhatsApp Web, через QR) и публикует статус из браузера: текст, картинку или видео, сразу или по московскому времени.

Контакты хранятся на сервере, а не в телефонной книге. У каждого номера есть источник:

- **Телефон** — загрузили файл с телефона (VCF, CSV, XLSX).
- **WhatsApp** — подтянули чаты и контакты, которые WhatsApp отдал после привязки.
- У одного человека могут стоять оба значка, если он есть и в файле, и в чатах.

## Важно: это не официальный WhatsApp Business API

Панель говорит с WhatsApp по неофициальному протоколу WhatsApp Web через библиотеку [Baileys](https://github.com/WhiskeySockets/Baileys). Это не API для бизнеса от Meta.

- Номер могут ограничить или заблокировать.
- Сначала проверяйте всё на запасной SIM, не на основном рабочем номере.
- В программе уже есть паузы: статус уходит пачками, между пачками и между публикациями есть задержка. Не ставьте паузы в ноль на живой аудитории.
- На своём телефоне отправленный отсюда статус иногда висит с пометкой «ожидание». У получателей он открывается как обычный статус.

## Что умеет

- Несколько номеров WhatsApp. QR в браузере, сессия лежит на диске и поднимается после перезапуска контейнера.
- Импорт телефонной книги: CSV (в том числе с `;` и в кодировке Windows-1251), XLSX, VCF. Номера приводятся к `+7`, повторы склеиваются.
- Синхронизация контактов из уже привязанного WhatsApp: чаты, контакты аккаунта и история, которую отдаёт протокол.
- Список контактов: поиск, метки, фильтр по источнику.
- Выгрузка базы в CSV и XLSX с тем же фильтром по источнику и метке.
- Публикация статуса: текст, картинка или видео, подпись, аудитория «оба источника / только чаты WhatsApp / только телефонная книга», плюс необязательная метка.
- Отправка сразу или по расписанию. Время в форме — московское (UTC+3).
- Большой список режется на пачки `statusJidList`. В карточке публикации виден прогресс и результат каждой пачки.
- Журнал и состояние связи по каждому номеру.
- Весь трафик WhatsApp (сокет, загрузка и скачивание медиа) можно пустить через HTTP- или SOCKS-прокси. Сама панель остаётся на прямом соединении.
- Вход по одному паролю из `.env`.

## Архитектура

```text
Браузер  →  панель (Node.js, Express)
              ├─ SQLite: контакты, источники, метки, очередь, журнал
              ├─ файлы сессий Baileys и готовые медиа
              ├─ планировщик публикаций
              └─ Baileys → WhatsApp Web (status@broadcast)
ffmpeg приводит картинку к JPEG и видео к MP4 (H.264, AAC).
```

Один процесс. Очередь публикаций — таблица в SQLite, отдельный воркер в том же процессе. Одновременно уходит одна публикация. Если контейнер остановили на середине, неотправленные пачки остаются в очереди и продолжаются после старта. Пачка, которую оборвали в момент отправки, может уйти повторно.

Аудитория считается в момент отправки, а не в момент постановки в очередь. Если до назначенного времени вы догрузите контакты, они попадут в статус.

## Требования

- VPS с Linux, удобнее Ubuntu 22.04 или 24.04.
- Docker и плагин Docker Compose.
- Свободные 1–2 ГБ RAM. Полная история чатов (`WA_SYNC_FULL_HISTORY=1`) просит больше.
- Исходящий доступ в интернет к серверам WhatsApp.
- Номер WhatsApp, желательно запасной, с которого вы готовы рискнуть.

## Установка на Ubuntu

Команды рассчитаны на чистый сервер под пользователем с `sudo`.

### 1. Docker

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl git
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc
. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu ${VERSION_CODENAME} stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt-get update
sudo apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
sudo usermod -aG docker "$USER"
```

Выйдите из SSH и зайдите снова, чтобы группа `docker` применилась. Проверка: `docker compose version`.

### 2. Код и настройки

```bash
git clone <адрес-этого-репозитория> wa-status-pro
cd wa-status-pro
cp .env.example .env
openssl rand -hex 32
```

Откройте `.env` и вставьте свой `ADMIN_PASSWORD` и вывод `openssl` в `SESSION_SECRET`. Пока пароль равен `change-me-please`, панель показывает предупреждение.

### 3. Запуск

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f app
```

Панель: `http://IP-СЕРВЕРА:8080`. Войдите паролем из `ADMIN_PASSWORD`.

Порт 8080 на первое время можно открыть в файрволе:

```bash
sudo ufw allow OpenSSH
sudo ufw allow 8080/tcp
sudo ufw enable
```

Когда появится домен и HTTPS, закройте 8080 снаружи и оставьте его только на localhost. Как это сделать — в разделе про Caddy.

### 4. Остановка и обновление

```bash
docker compose stop
docker compose pull   # если позже появится готовый образ; сейчас образ собирается локально
git pull
docker compose up -d --build
```

Данные лежат в томе Docker `wa-status-pro_wa_data` и при пересборке образа не пропадают.

## Прокси, если сервер в России

С российского VPS WhatsApp часто режет прямой доступ: QR мигает, а в журнале крутится переподключение. Прокси должен стоять там, где WhatsApp открывается нормально (VPS вне РФ, или свой SOCKS). Через него идут:

- websocket к `wss://web.whatsapp.com`;
- загрузка видео и картинок статуса;
- скачивание истории и служебных файлов WhatsApp.

Страницы панели, вход и статика к прокси не ходят. Браузер по-прежнему открывает ваш домен напрямую.

В `.env`:

```bash
# DNS WhatsApp резолвится на прокси, не у российского провайдера
WA_PROXY_URL=socks5h://user:p%40ss@203.0.113.10:1080
```

Если в пароле есть `@`, `:`, `/` или пробел, закодируйте их (`@` → `%40`, `:` → `%3A`). Логин и пароль в журнал и на страницу «Журнал» не попадают: там будет `socks5h://203.0.113.10:1080`.

`socks5://` резолвит имя назначения на самом VPS. `socks5h://` делает это на прокси. Для России берите `socks5h`. `http://` и `https://` — обычный HTTP-прокси с методом CONNECT.

После `docker compose up -d` в логах должна быть строка `Трафик WhatsApp идёт через прокси ...` без пароля. На странице **Журнал** тот же адрес и кнопка **Проверить прокси**: панель открывает `https://web.whatsapp.com` тем же каналом и показывает задержку или текст ошибки. Отдельный прокси на каждый номер в этой версии не задаётся, только общая переменная.

Пока идёт QR, панель не ждёт минуту молча: истёкший код обновляется примерно через секунду, предыдущая картинка остаётся на экране, опрос страницы не блокирует остальные запросы. Длинная пауза (до 60 секунд) остаётся только у уже привязанного номера, который потерял связь, чтобы не долбить WhatsApp.

## Как подключить номер

1. В панели: **Номера** → название, например «Основной блог» → **Добавить номер**.
2. Откроется страница с QR. Она обновляется сама.
3. На телефоне: WhatsApp → **Связанные устройства** → **Привязка устройства** → сканируйте QR.
4. Состояние сменится на «Подключён», появится номер. В списке устройств телефона будет **WA Status Pro**.
5. После перезапуска сервера сессия поднимается сама, QR заново не нужен, пока вы сами не нажмёте **Отвязать** или пока WhatsApp не сбросит устройство.

Если QR не появляется: подождите полминуты, нажмите **Подключить снова**, смотрите **Журнал**. Частая причина — с сервера нет выхода в сеть WhatsApp.

Кнопка **Отвязать** завершает сессию на стороне WhatsApp. **Удалить** убирает номер из панели и тоже отвязывает устройство. Контакты в общей базе при этом остаются.

## Откуда берутся контакты

### Телефонная книга — файл

Загрузка на странице **Контакты** ставит источник **Телефон**.

Подходят:

- CSV. Русский Excel обычно сохраняет с разделителем `;` и иногда в Windows-1251 — это читается. Подойдёт и обычный CSV с запятой.
- XLSX. Старый `.xls` нужно пересохранить как `.xlsx`.
- VCF / vCard, в том числе с `ENCODING=QUOTED-PRINTABLE` и параметром `WAID`.

Столбцы можно назвать по-русски или по-английски: `телефон` / `phone` / `номер` / `Phone 1 - Value`, `имя` / `name`, `метки` / `tags` / `Group Membership`. Несколько телефонных столбцов дают несколько карточек с одним именем. Метки делятся запятой, точкой с запятой, `|` или ` ::: `.

Пример CSV — `examples/contacts.csv`:

```csv
телефон;имя;метки
+7 (928) 000-00-01;Аминат;vip
89280000002;Зарема;vip|грозный
9280000003;Малика;чечня
```

Так же принимаются `+7 (928) 000-00-01`, `8 928 000-00-02`, `9280000003`, `79280000004`. В базе остаётся единый вид `+7`. Десять цифр без девятки в начале не угадываются и попадут в отчёт об ошибках. Номера не из России в эту базу не кладутся: аудитория панели — номера `+7`.

Повтор того же номера не создаёт вторую карточку. Метки складываются. Уже записанное имя не затирается пустым и не затирается более слабым именем из WhatsApp (пуш-имя). Имя из телефонной книги заполняет пустую карточку.

Примеры файлов: `examples/contacts.csv`, `examples/contacts.vcf`, `examples/google-contacts.csv`.

### Что WhatsApp отдаёт сам, а что нет

Кнопка **Синхронизировать контакты из WhatsApp** на странице номера забирает в базу то, что библиотека уже получила после QR:

- контакты, которые WhatsApp хранит в самом аккаунте (имя, если оно там есть);
- личные чаты из истории, которую телефон отдал связанному устройству;
- пары «скрытый LID → номер», если протокол их прислал.

Этим карточкам ставится источник **WhatsApp**. Если такой номер уже был из файла, значок **Телефон** остаётся, получается оба источника.

В эту выгрузку не попадает телефонная книга целиком. Человек, которого вы только сохранили в контактах телефона и с которым не было переписки, а WhatsApp его в облако аккаунта не синхронизировал, в панели не появится. Группы, рассылки и каналы тоже не импортируются: статус уходит личным номерам. Сообщения из чатов на диск не пишутся, из них берётся только номер и имя.

Сразу после QR список может быть пустым: история доезжает минуту или дольше. На странице номера есть счётчик «В кэше WhatsApp». Когда число перестало расти, нажмите синхронизацию. Повторная синхронизация безопасна: дублей не будет.

`WA_SYNC_FULL_HISTORY=1` просит более глубокую историю чатов. Имеет смысл, если в «недавних» не хватает старых переписок. Телефон в этот момент должен быть онлайн.

Полную книгу контактов по-прежнему даёт файл VCF или CSV. Это основной путь, если аудитория сидит в адресной книге и не обязательно писала вам в чат.

### Как выгрузить книгу с Android

Путь зависит от прошивки.

Чистый Android и многие оболочки:

1. Откройте приложение **Контакты**.
2. Меню (три полоски или три точки).
3. **Настройки** или **Упорядочить** → **Импорт и экспорт**.
4. **Экспорт в файл VCF** / **Экспорт на накопитель**.
5. Файл окажется в «Загрузках». Перешлите его на компьютер и загрузите в панели.

Samsung: Контакты → меню → **Управление контактами** → **Импорт/экспорт контактов** → экспорт в память устройства.

Xiaomi / HyperOS: Контакты → настройки → **Импорт и экспорт** → экспорт на устройство.

Через Google, если контакты телефона сидят в аккаунте Google:

1. На компьютере откройте [contacts.google.com](https://contacts.google.com) под тем же аккаунтом.
2. **Исправить и управлять** → **Экспорт**.
3. Формат **vCard** или CSV Google.
4. Загрузите файл в панель. CSV Google с колонками `Name` и `Phone 1 - Value` разбирается.

### Как выгрузить книгу с iPhone

В приложении «Контакты» на самом iPhone нет кнопки «скачать всю книгу». Рабочий путь — iCloud.

1. На iPhone: **Настройки** → ваше имя → **iCloud** → **Контакты** включены, книга успела синхронизироваться.
2. На компьютере откройте [icloud.com/contacts](https://www.icloud.com/contacts) и войдите в тот же Apple ID.
3. Выделите нужные контакты или все.
4. Шестерёнка слева внизу → **Экспортировать vCard**.
5. Полученный `.vcf` загрузите в панели.

Если рядом есть Mac с тем же Apple ID: приложение **Контакты** → меню **Файл** → **Экспортировать** → **Экспортировать vCard**.

## Фильтр, аудитория и выгрузка

На странице контактов фильтр источника:

- **Все источники** — вся база.
- **Чаты WhatsApp** — есть значок WhatsApp (даже если есть и телефон).
- **Телефонная книга** — есть значок телефона.
- **Есть в обоих** — номер пришёл и файлом, и из WhatsApp.

Кнопки **CSV** и **XLSX** скачивают текущий фильтр: источник, метка и строка поиска. В файле колонки «Телефон», «Имя», «Метки», «Источники». CSV с BOM и разделителем `;`, чтобы открылся в русском Excel. Если Excel превращает номера в экспоненту, берите XLSX: там телефон записан текстом.

В форме публикации аудитория задаётся так же и складывается с меткой:

- **Оба источника** — вся база, метка по желанию.
- **Только чаты WhatsApp** — у кого есть источник WhatsApp. Человек с обоими значками сюда входит.
- **Только телефонная книга** — у кого есть источник Телефон.

Пустая метка означает «не фильтровать по метке». Форма сразу показывает, сколько людей попадёт в отправку и сколько будет пачек.

## Как опубликовать статус

1. Номер должен быть в состоянии «Подключён». Для отправки «сейчас» в выбранной аудитории уже должны быть люди. Запланированную публикацию можно поставить заранее: получатели посчитаются в момент отправки.
2. Откройте **Мои статусы**. Там же форма «Опубликовать статус» с предпросмотром, как карточка в WhatsApp.
3. Выберите номер, тип (текст, изображение, видео), аудиторию и метку.
4. **Сейчас** или **Запланировать**. Дата в календаре — московское время, без перевода на летнее.
5. Откроется карточка с прогрессом. В журнале по каждой пачке написано, скольким людям она ушла и какой id вернул WhatsApp.

Ваш собственный номер добавляется в каждую пачку `statusJidList`. Без этого статус, отправленный со связанного устройства, на телефоне в «Моём статусе» не появляется: WhatsApp показывает его только тем jid, которые перечислены, включая вас. В списке это `7999…@s.whatsapp.net` без суффикса устройства `:12`.

Между публикациями есть пауза `MIN_PUBLISH_INTERVAL_MS` (по умолчанию 20 секунд). Форма показывает обратный отсчёт. Пока одна публикация в состоянии «Публикуется», следующая ждёт в очереди. Если отправка зависла дольше 8 минут или WhatsApp не ответил за 90 секунд, задача становится «Ошибка», очередь освобождается, и на карточке есть **Повторить**. Повтор снова ставит неудачные пачки в очередь и не ждёт паузу. Уже ушедшие пачки повторно не отправляются.

Остановить можно публикацию в очереди, по расписанию или ту, что ещё идёт: кнопка **Остановить**.

Если получателей больше размера пачки, у вас в ленте может быть несколько копий одного ролика: у каждой копии свой список зрителей. Конкретный человек видит статус один раз. Если пачка падает, в журнале будет текст ошибки WhatsApp. Тогда уменьшите `STATUS_BATCH_SIZE` и увеличьте паузу.

### Видео

WhatsApp всё равно пережимает статус у себя. Если отправить тяжёлый или «кривой» файл, вторая перекодировка сильнее портит картинку. Поэтому панель заранее приводит ролик к тому, что WhatsApp переваривает легче:

- H.264, профиль High, `yuv420p`, AAC;
- вписывается в 720×1280, пропорции сохраняются, маленькое видео не растягивается;
- около 2,5 Мбит/с, потолок 3 Мбит/с, `faststart`;
- длина не больше `MAX_VIDEO_SECONDS`.

Если файл уже такой, перекодирование пропускается и только снимается кадр-превью. Превью (`jpegThumbnail`) уходит вместе со статусом, чтобы Baileys не читал весь ролик в память. Одновременно работает только один ffmpeg, в один поток: на VPS с 768 МБ памяти параллельное кодирование легко роняет процесс. Картинка приводится к JPEG в том же пределе 720×1280.

### Мои статусы и просмотры

**Мои статусы** — лента как в приложении: кольцо, полноэкранная карточка, подпись, время и сколько осталось из 24 часов. Значок 👁 открывает список зрителей: имя, телефон, время, новее сверху. Есть поиск, фильтр по источнику и метке и выгрузка CSV.

WhatsApp присылает квитанцию просмотра только если у зрителя включены отчёты о прочтении. Поэтому число в панели может быть меньше, чем счётчик в телефоне. Доставка без открытия в просмотры не пишется. Свой номер в список зрителей не попадает.

## Домен и HTTPS

После проверки по IP закройте панель с интернета и пустите её через Caddy.

В `docker-compose.yml` замените проброс порта на локальный:

```yaml
ports:
  - "127.0.0.1:8080:8080"
```

Рядом поднимите Caddy. Пример `deploy/Caddyfile` проксирует домен на сервис `app`. Короткий вариант отдельным compose в том же каталоге, файл `docker-compose.caddy.yml` создавать не обязательно — можно добавить сервис в основной файл:

```yaml
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - "80:80"
      - "443:443"
    environment:
      DOMAIN: status.example.com
    volumes:
      - ./deploy/Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    depends_on:
      - app
```

И том `caddy_data`, `caddy_config` в секции `volumes`. DNS домена должен смотреть на IP сервера. В `.env` поставьте `COOKIE_SECURE=1` и перезапустите: `docker compose up -d`.

Тот же прокси на nginx:

```nginx
server {
    listen 443 ssl;
    server_name status.example.com;
    client_max_body_size 64m;

    # сертификаты certbot или свои
    ssl_certificate     /etc/letsencrypt/live/status.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/status.example.com/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

`client_max_body_size` не должен быть меньше `MAX_UPLOAD_MB`.

## Резервные копии

В томе лежат база SQLite, файлы сессии WhatsApp и подготовленные медиа. Сессия — это вход в номер. Храните копию так же бережно, как пароль.

Согласованная копия на остановленном контейнере:

```bash
docker compose stop
mkdir -p "$HOME/wa-backups"
docker run --rm \
  -v wa-status-pro_wa_data:/data:ro \
  -v "$HOME/wa-backups":/backup \
  alpine tar czf /backup/wa-data-$(date +%F).tar.gz -C /data .
docker compose start
```

Восстановление в пустой том:

```bash
docker compose stop
docker run --rm \
  -v wa-status-pro_wa_data:/data \
  -v "$HOME/wa-backups":/backup \
  alpine sh -c 'rm -rf /data/* && tar xzf /backup/ИМЯ-АРХИВА.tar.gz -C /data'
docker compose start
```

Имя тома смотрите командой `docker volume ls`: оно начинается с `wa-status-pro_`. Копировать каталог на живом контейнере можно, но файл SQLite тогда лучше снимать вместе с `app.sqlite-wal`. Остановка надёжнее.

Раз в неделю копируйте архив с VPS к себе. Потеря тома означает новый QR и пустую базу контактов.

## Если что-то пошло не так

- Панель не открывается: `docker compose ps` и `docker compose logs app`. Чаще всего нет `.env` или пароль короче 8 символов.
- После входа сразу выбрасывает на форму: по HTTPS включите `COOKIE_SECURE=1`, по голому HTTP оставьте `0`.
- QR не появляется или в журнале повторяется «Нет связи с WhatsApp»: с сервера не открывается WhatsApp. Задайте `WA_PROXY_URL` и нажмите **Проверить прокси** на странице журнала. Код 401 — сессию сбросили, сканируйте QR заново. Код 403 — номер могли ограничить, остановитесь и не долбите переподключением.
- QR на экране обновляется сам примерно раз в минуту, предыдущая картинка остаётся, пока готовится следующая. Пауза в десятки секунд без кода бывает у уже привязанного номера, который потерял связь: так панель не долбит WhatsApp.
- «WhatsApp ещё не передал контакты»: подождите, пока вырастет счётчик кэша. Для людей без переписки грузите VCF.
- Импорт пишет «не найден столбец телефона»: в первой строке нужно слово `телефон`, `phone` или `номер`. Либо уберите шапку и оставьте столбец номеров.
- Публикация стоит в очереди с текстом «Номер не на связи»: дождитесь состояния «Подключён». Планировщик сам повторит.
- Видео не уходит: в журнале будет хвост ошибки ffmpeg. Проверьте, что файл — обычное видео, не битая загрузка.
- Статус в панели «Опубликован», а на своём телефоне пусто: в журнале должна быть строка «и ваш номер». Если её нет, сессия не сообщила JID — нажмите «Подключить снова».
- Вторую публикацию не берёт: посмотрите карточку. Если написано «Публикуется» дольше обычного, через 8 минут она сама станет ошибкой, и очередь освободится. Кнопка **Повторить** есть у ошибки и частичной отправки. Если идёт отсчёт паузы, дождитесь нуля: это `MIN_PUBLISH_INTERVAL_MS`.
- Статус ушёл, а зритель его не видит: в аудитории должен быть именно его номер в формате `+7`, и пачка с этим номером должна быть «Отправлено». Пустой список зрителей WhatsApp никому не показывает.

## Ограничения

- Неофициальный протокол, риск ограничения номера, см. начало этого файла.
- В базу попадают только российские номера `+7`.
- Полная телефонная книга через QR не выгружается. Для неё нужен файл.
- Большая аудитория — это несколько статусов-копий у отправителя.
- На телефоне отправителя статус может отображаться как «ожидание», даже когда ваш номер есть в списке. У получателей он при этом открывается.
- Счётчик просмотров в панели не включает людей, у которых выключены отчёты о прочтении.
- Один администратор, без личных кабинетов и оплаты.
- Тексты переписок не сохраняются, но телефон на время синхронизации истории отдаёт их связанному устройству. Не включайте полную историю на номере, где этого хотите избежать.
- Панель не заменяет телефон: исходящие личные сообщения отсюда не отправляются, только статус.

## Дальше: много блогеров

Сейчас это инструмент одного владельца на своём сервере. Следующий этап, если понадобится сервис для многих блогеров:

- отдельные аккаунты, у каждого свои номера, контакты и очередь;
- изоляция сессий и квот на размер аудитории и частоту статусов;
- регистрация, роли «владелец сервиса» и «блогер»;
- оплата (для этой аудитории логично смотреть ЮKassa) и отключение просроченных кабинетов;
- отдельные резервные копии по кабинету.

Этого в текущей версии нет. Ставить одну общую базу на несколько незнакомых людей не стоит: сессия WhatsApp и список номеров — это доступ к их аудитории.

## Разработка

Нужны Node.js 22, ffmpeg и зависимости из `package.json`.

```bash
cp .env.example .env
# задайте ADMIN_PASSWORD и SESSION_SECRET
npm install
npm test
npm run lint
npm run typecheck
npm run dev
```

Панель поднимется на порту из `.env`, данные лягут в `./data`. Тесты покрывают нормализацию `+7`, разбор CSV/XLSX/VCF, склейку источников, фильтр аудитории, пачки `statusJidList` и очередь публикаций. Живой QR в автоматических тестах не сканируется: его проверяете вы на сервере.
